# 1. Product First, Testing Second

# 3. What Is Automation Testing?

Suppose we perform this test 100 times:

```text
Open application
      ↓
Enter username
      ↓
Enter password
      ↓
Click Login
      ↓
Verify Dashboard
```

Doing this manually every time is inefficient.

So we create a program that performs these steps automatically.

That is an:

> **Automation Script**

Conceptually:

```text
Test Case
   ↓
Automation Script
   ↓
Browser
   ↓
Application
   ↓
Result
```

But remember:

> **Writing an automation script is not the same as Automation Testing.**

Automation Testing is a complete engineering process.

# 4. Manual Testing + Automation Testing

Manual Testing and Automation Testing are not enemies. Manual testing allows a human to explore and discover unexpected behavior.Automation is excellent for repeatable scenarios.

For example:

```text
Manual Testing
    ↓
Explore
    ↓
Understand
    ↓
Discover Scenarios
    ↓
Create Test Cases
```

Then:

```text
Automation Testing
    ↓
Select Repeatable Scenarios
    ↓
Create Automation Scripts
    ↓
Execute
    ↓
Report
```

Automation should reduce repetitive work, not eliminate engineering thinking.

# 8. Change the Mindset — “I Am a Tester”

> **“I am a Software Engineer.”**

# 10. Authentication Example

Requirement:

> **Only a valid user should be allowed to enter the system.**

Now analyse the requirement.

Registration:

```text
Customer
   ↓
Enter Personal Details
   ↓
Validate Data
   ↓
Create Account
```

Now ask:

* Is username unique?
* Is email valid?
* What is the password policy?
* Which fields are mandatory?
* What happens with invalid data?
* What happens with duplicate users?

This is **analysis**.


## 🛠️ Hands-on Exercise 10 — Requirement Analysis

Take this requirement:

> “Only registered users should be allowed to log in.”

Now write at least **10 questions** that a Software Engineer should ask before implementing or testing it.

Examples:

* What makes a user “registered”?
* Can an inactive user log in?
* What happens after multiple failed attempts?
* Is the username case-sensitive?
* Is the password case-sensitive?

### Challenge

Convert your questions into acceptance criteria.

Example:

```text
Requirement:
Only registered users can log in.

Acceptance Criterion:
Given a registered and active user,
when valid credentials are entered,
then the user should be redirected to the Dashboard.
```

# 14. AI + Automation — The New Engineering Loop

Traditional:

```text
Requirement
     ↓
Human writes test cases
     ↓
Human writes automation
     ↓
Human executes
     ↓
Human analyses failures
```

AI-assisted:

```text
Requirement
     ↓
AI assists analysis
     ↓
AI suggests scenarios
     ↓
Engineer reviews
     ↓
AI assists automation
     ↓
Engineer validates
     ↓
Automation executes
     ↓
AI assists failure analysis
     ↓
Engineer makes final decision
```

Therefore:

> **AI makes execution faster; it does not replace engineering judgment.**
