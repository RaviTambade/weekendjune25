 
## JavaScript Fundamentals — Variables, Functions and Modules

> **Mentor Thought:**
> A good software engineer does not put everything into one file.
> A good software engineer learns to **divide a problem into small responsibilities** and place each responsibility in the right module.


# 1. Start With a Simple Story

Imagine we are building an **Insurance Application**.Today we want to calculate a customer's premium.A beginner may write everything in one file:

```text
test.js
 ├── customer data
 ├── premium calculation
 ├── tax calculation
 ├── policy validation
 └── output
```

It works. But as the application grows, `test.js` becomes huge. A professional developer asks: "Why should one file know everything?" So we separate responsibilities:

```text
insurance-app/
│
├── policy.js
├── premium.js
├── customer.js
└── test.js
```

Now each file has a clear responsibility. This is our first introduction to:

# Separation of Concerns

> **One module should have one clear responsibility.**


# 2. What Is a Variable?

A variable is simply a **named place to store a value**. For example:

```javascript
let age = 25;
let name = "Ravi";
let premium = 15000;
```

Think of a variable as a box.

```text
age     ──────> 25

name    ──────> "Ravi"

premium ──────> 15000
```

JavaScript provides:

```javascript
let
const
var
```

For modern JavaScript, prefer:

```javascript
const
```

and use:

```javascript
let
```

when the value needs to change.

Example:

```javascript
const policyNumber = "POL1001";

let premium = 10000;

premium = 12000;
```


# 3. `const` vs `let`

### `const`

Use when the variable should not be reassigned.

```javascript
const name = "Ravi";
const age = 25;
```

This is not allowed:

```javascript
age = 30;
```

### `let`

Use when the value can change.

```javascript
let balance = 10000;

balance = balance + 5000;
```

Now:

```text
balance
   ↓
10000
   ↓
15000
```

# 4. What Is a Function?

A function is a **reusable piece of logic**. Suppose we want to calculate insurance premium. Instead of writing:

```javascript
let age = 30;
let basePremium = 10000;

let premium = basePremium;

if (age > 40) {
    premium = premium + 5000;
}
```

every time, we can create a function:

```javascript
function calculatePremium(age, basePremium) {

    let premium = basePremium;

    if (age > 40) {
        premium = premium + 5000;
    }

    return premium;
}
```

Now we can reuse it:

```javascript
let premium1 = calculatePremium(30, 10000);
let premium2 = calculatePremium(50, 10000);
```

# 5. Function Thinking

A function can be visualized as a machine:

```text
              INPUT
                |
                v
        +----------------+
        |    FUNCTION    |
        |                |
        | business logic |
        +----------------+
                |
                v
              OUTPUT
```

For example:

```text
age = 50
basePremium = 10000

        ↓

calculatePremium()

        ↓

15000
```

This gives us a very important software engineering idea:

> **Input → Processing → Output**


# 6. Why Should Functions Be Separate?

Suppose `test.js` contains:

```javascript
function calculatePremium(age, basePremium) {
    let premium = basePremium;

    if (age > 40) {
        premium += 5000;
    }

    return premium;
}

function calculateTax(premium) {
    return premium * 0.18;
}

function calculateFinalAmount(premium, tax) {
    return premium + tax;
}
```

This is okay for a small demonstration. But imagine 50 functions. Then:

```text
test.js
--------------------
calculatePremium()
calculateTax()
calculateFinalAmount()
validatePolicy()
calculateCommission()
calculateClaim()
...
50 more functions
```

Now the file becomes difficult to understand. So we separate them.

# 7. Introducing Modules

A **module** is a separate JavaScript file containing related variables and functions.

For example:

```text
insurance-app/
│
├── premium.js
├── tax.js
└── test.js
```

Responsibilities:

```text
premium.js
     ↓
Premium-related logic

tax.js
     ↓
Tax-related logic

test.js
     ↓
Uses the modules
```

This is **Separation of Concerns**.


# 8. Create `premium.js`

Let's create our first module.

### `premium.js`

```javascript
function calculatePremium(age, basePremium) {

    let premium = basePremium;

    if (age > 40) {
        premium = premium + 5000;
    }

    return premium;
}

module.exports = {
    calculatePremium
};
```

Notice something important.

We have:

```javascript
module.exports
```

We are saying: "This function is available to other JavaScript files."


# 9. Create `test.js`

Now create:

### `test.js`

```javascript
const premiumModule = require("./premium");

let age = 45;
let basePremium = 10000;

let premium =
    premiumModule.calculatePremium(age, basePremium);

console.log("Premium:", premium);
```

Run:

```bash
node test.js
```

Output:

```text
Premium: 15000
```

# 10. What Happened Behind the Scenes?

Our `test.js` contains:

```javascript
const premiumModule = require("./premium");
```

Node.js loads:

```text
premium.js
```

Then:

```javascript
module.exports = {
    calculatePremium
};
```

makes the function available.

So conceptually:

```text
              test.js
                 |
                 |
              require()
                 |
                 v
            premium.js
                 |
                 v
       calculatePremium()
                 |
                 v
              result
```

# 11. A Better Way to Import

Instead of:

```javascript
const premiumModule = require("./premium");

premiumModule.calculatePremium(45, 10000);
```

we can directly extract the function:

```javascript
const {
    calculatePremium
} = require("./premium");

let premium = calculatePremium(45, 10000);

console.log(premium);
```

This is cleaner.

# 12. Multiple Functions in One Module

Suppose our insurance business has:

```text
calculatePremium()
calculateDiscount()
calculateTax()
```

Create:

### `insurance.js`

```javascript
function calculatePremium(age, basePremium) {

    let premium = basePremium;

    if (age > 40) {
        premium += 5000;
    }

    return premium;
}

function calculateDiscount(premium, discountPercentage) {

    return premium -
        (premium * discountPercentage / 100);
}

function calculateTax(amount) {

    return amount * 0.18;
}

module.exports = {
    calculatePremium,
    calculateDiscount,
    calculateTax
};
```


# 13. Use the Module From `test.js`

```javascript
const {
    calculatePremium,
    calculateDiscount,
    calculateTax
} = require("./insurance");

const age = 45;
const basePremium = 10000;

const premium =
    calculatePremium(age, basePremium);

const discountedPremium =
    calculateDiscount(premium, 10);

const tax =
    calculateTax(discountedPremium);

const finalAmount =
    discountedPremium + tax;

console.log("Premium:", premium);
console.log("Discounted Premium:", discountedPremium);
console.log("Tax:", tax);
console.log("Final Amount:", finalAmount);
```

Output:

```text
Premium: 15000
Discounted Premium: 13500
Tax: 2430
Final Amount: 15930
```

# 14. Now Let's Improve the Architecture

Instead of putting everything in `insurance.js`, let's separate responsibilities.

```text
insurance-app/
│
├── premium.js
├── discount.js
├── tax.js
└── test.js
```

Each module has one responsibility.

### `premium.js`

```javascript
function calculatePremium(age, basePremium) {

    let premium = basePremium;

    if (age > 40) {
        premium += 5000;
    }

    return premium;
}

module.exports = {
    calculatePremium
};
```

### `discount.js`

```javascript
function calculateDiscount(amount, percentage) {

    return amount -
        (amount * percentage / 100);
}

module.exports = {
    calculateDiscount
};
```

### `tax.js`

```javascript
function calculateTax(amount) {

    return amount * 0.18;
}

module.exports = {
    calculateTax
};
```

# 15. `test.js` Becomes Very Clean

```javascript
const {
    calculatePremium
} = require("./premium");

const {
    calculateDiscount
} = require("./discount");

const {
    calculateTax
} = require("./tax");


const age = 45;
const basePremium = 10000;

const premium =
    calculatePremium(age, basePremium);

const discountedPremium =
    calculateDiscount(premium, 10);

const tax =
    calculateTax(discountedPremium);

const finalAmount =
    discountedPremium + tax;


console.log("Premium:", premium);
console.log("Discount:", premium - discountedPremium);
console.log("Tax:", tax);
console.log("Final Amount:", finalAmount);
```

Now look at our architecture:

```text
                 test.js
                    |
       +------------+------------+
       |            |            |
       v            v            v
   premium.js   discount.js    tax.js
       |            |            |
       v            v            v
   Premium       Discount       Tax
    Logic         Logic         Logic
```

This is much easier to maintain.

# 16. The Important Principle

This is not just a JavaScript concept. It is a **software engineering principle**. We call it:

## Separation of Concerns

Different concerns should be separated. For example:

```text
Customer logic
       ↓
customer.js

Policy logic
       ↓
policy.js

Premium logic
       ↓
premium.js

Claim logic
       ↓
claim.js

Payment logic
       ↓
payment.js

Testing / execution
       ↓
test.js
```

# 17. From Beginner Code to Professional Code

### Beginner approach

```text
test.js
│
├── variables
├── calculations
├── validation
├── business logic
├── database logic
├── output
└── everything else
```

### Better approach

```text
project/
│
├── customer.js
├── policy.js
├── premium.js
├── claim.js
├── payment.js
└── test.js
```

### Enterprise approach

Eventually, this idea grows into:

```text
src/
│
├── controllers/
├── services/
├── repositories/
├── models/
├── utilities/
└── config/
```

The principle remains the same: **Put related responsibilities together and unrelated responsibilities apart.**

# 22. The Transflower Learning Formula

Remember this progression:

```text
VARIABLE
   ↓
stores data

FUNCTION
   ↓
encapsulates logic

MODULE
   ↓
groups related logic

SEPARATION OF CONCERNS
   ↓
separates responsibilities

APPLICATION
   ↓
combines modules to solve a business problem
```

And the most important lesson:  **Don't ask only "How do I write this code?"**  Ask: **"Where should this code live?"** That question is what starts transforming a **coder into a software engineer**.
